체험첵! 올리기 전 시험 규칙

1. 단순 수정 (글귀, 색, 여백, 그림 교체) → 코드 검사만 하고 올린다.
     python3 tests/check.py
   - 문법 오류(따옴표·괄호 짝 포함): 모든 .js 파일과 HTML 안의 스크립트
   - 단추가 가리키는 처리가 실제로 있는지: data-act 단추, AI 단추, 초안 단추, onclick 함수
   - 판 번호가 파일마다 같은지: 같은 파일의 ?v= 번호, 앱 판 번호(APP_VERSION) = 서비스 워커 캐시 이름,
     서비스 워커가 미리 저장하는 파일이 실제로 있는지

2. 기능 수정 (새 기능, 화면 배치 변경, 서버·저장 방식 수정) → 전체 시험을 하고 올린다.
     python3 tests/full_test.py
   - 코드 검사를 먼저 돌리고, 통과하면 화면을 실제로 띄워 한 번씩 밟아 본다.
   - 선생님: 체험학습 만들기(반 2개), 업무 일정 자동, 장소→날씨, 업무 체크, 학생·교사 준비물,
     안전 교육, 사전·사후 설문, 활동지, 인원 점검, 당일 탭 자동, 인원 점검 번호판, 설정 팝업
   - 학생 제출·저장: 준비물 "다 챙겼어요", 사전 설문, 모둠 활동지, 안전 교육 시청 체크,
     인원 점검(정해진 시간 안), 사후 설문, 일정표 보기
   - 문서·공유: 설문 결과 정리, 사전 안내 자료, 결과 보고서, 초안 저장, 자료 공유 → 불러오기
   - 모바일: 섹션 접기, 머리 설정 단추 숨김 / 미리보기(?demo) 두 체험학습의 모든 탭
   - 체험 모드로 돌아서 진짜 자료는 건드리지 않는다. 카카오·날씨·유튜브·로그인·AI는 가짜 응답.
   - 필요한 것: python3, node, playwright(크로미움)

3. 어느 쪽인지 애매하면 전체 시험을 한다.
4. 시험에서 하나라도 걸리면 올리지 말고 먼저 고친다.
5. 올린 뒤에는 어떤 시험을 돌렸고 결과가 어땠는지 한 줄로 알린다.

새 기능을 넣으면 그 기능을 밟는 항목도 tests/full_test.py 에 더한다.
